THE BOUNDARY

The boundary: CI, post-merge, scheduled

IN CI

Failure means: this commit must not merge.

  • Build and compile
  • Unit and fast integration
  • Lint and type checks

AFTER THE MERGE

Only answerable once the merged result exists.

  • Deploy to staging
  • End-to-end on a real env
  • Post-deploy smoke tests

ON A SCHEDULE

The answer does not change commit to commit.

  • Full OS and browser matrix
  • Licence and CVE audits
  • Long soak and fuzz runs

The test: ask what a failure here would mean. If the answer is not “do not merge this commit”, it is not a CI stage.
