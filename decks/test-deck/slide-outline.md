## slide-02 — 지금 무엇이 달라졌는가
- 헤더바: 장 번호 칩 `01` + 타이틀 "지금 무엇이 달라졌는가"
- 3열 구성, 열 사이 1px `#C5D2E3` 헤어라인. 각 열 상단에 번호 칩 01·02·03
  - 01 도구에서 동료로 — 결과물을 제안하는 단계를 넘어, 정해진 절차를 스스로 수행하는 단계로 이동한다.
  - 02 문서에서 프로세스로 — 자동화 대상이 개별 문서 작성에서 조회·승인·보고로 이어지는 업무 흐름 전체로 넓어진다.
  - 03 IT에서 현업으로 — 자동화를 만드는 주체가 개발 조직에서 업무를 가장 잘 아는 담당자로 옮겨간다.
- 하단 info 콜아웃: "질문이 바뀌었다. 'AI가 무엇을 할 수 있는가'가 아니라 '어떤 업무를 맡길 것인가'."
- 데이터 없음 — 진단은 방향 서술로만. 지어낸 통계 금지.

## slide-03 — 업무 자동화의 3단계
- 헤더바: 장 번호 칩 `02` + 타이틀 "업무 자동화는 3단계로 성숙한다"
- 프로세스 플로우(가로 3단계). 노드는 흰 배경 + 1px `#C5D2E3`, 좌상단 번호 칩, 직각 커넥터(1.75pt `#1B66C9`, 삼각 화살촉, 곡선 없음)
  - 01 보조 — 사람이 실행하고 AI는 초안과 검색을 돕는다. 산출물 책임은 전적으로 사람.
  - 02 위임 (현재 구간 · active 강조: `#E8F1FB` 채움 + 좌측 4px `#1B66C9`) — 절차가 고정된 업무를 AI가 실행하고 사람이 검수한다.
  - 03 자율 — AI가 실행·판단하고 사람은 예외와 기준만 관리한다.
- 각 단계 아래 캡션 한 줄: 사람의 역할이 어떻게 이동하는지(실행자 → 검수자 → 기준 설계자)
- 하단 info 콜아웃: "2단계로 넘어가는 문턱은 모델 성능이 아니라 검수 기준과 책임 소재의 정의다."
- 다이어그램 원칙: 텍스트는 의미 태그(h3/p)로 유지하고, 커넥터·화살촉만 인라인 SVG로 그린다.

## slide-04 — 도입 조직이 먼저 준비해야 할 것
- 헤더바: 장 번호 칩 `03` + 타이틀 "도입 조직이 먼저 준비해야 할 것"
- 2열 비교 구성, 각 열 상단 navy 헤더 밴드
  - 좌 "먼저 할 일" (KRDS 블루 사각 마커, 3항목)
    - 반복도와 규칙성이 높은 업무부터 목록으로 만든다
    - 사람이 최종 확인할 지점을 업무마다 명시한다
    - 잘못 실행됐을 때 되돌리는 절차를 함께 설계한다
  - 우 "미루면 위험한 것" (warning 콜아웃, 좌측 4px `#E03B3B`, 3항목)
    - 검수 지점 없는 전면 적용
    - 실행 근거를 남기지 않는 자동화
    - 직무 재설계 없는 도구만의 도입
- 하단 summary 콜아웃('요약' navy 칩): "성패는 모델 성능이 아니라, 사람이 어디서 개입할지 정하는 설계에서 갈린다."
